# Go 御魂强化推荐器

读取简洁的御魂 JSON，复用上级项目的御魂路线配置与 `yuhun/yys_export/ios.json` 御魂池，输出强化建议、动态 Top N 门槛、精确达标概率、期望分、分位数和各有效属性未来 roll 次数分布。

## 运行

```powershell
cd go_recommender
go run . -input sample.json
```

机器可读输出：

```powershell
go run . -input sample.json -json
```

`position` 使用玩家习惯的 **1-6号位**，不是 Python 内部的 0-5 下标。程序默认从当前项目自动定位 `yuhun`；在其他目录运行时可传 `-data-root D:\path\to\yuhun`。

## 概率模型

- 从当前等级计算到 +15，每 +3 发生一次事件。
- 少于4条副属性时，仍从完整的可用副属性池（排除主属性）抽取：抽到已有属性就强化，抽到没有的属性就新增。
- 满4条后，每条副属性各有 25% 概率获得一次强化。
- 初始已知数值按 `实际值 / 单次最大值` 计分；未来每次 roll 在最大值的 80%-100% 之间均匀分布。
- 对每条强化选择路径进行完整枚举；roll 数值概率使用加权均匀和的解析分布计算，不依赖蒙特卡洛抽样，因此输出可重复。
- 动态门槛为现有池中“同套装、同位置、同主属性”的 Top N 分数与路线最低分的较大值。

参考 Python 实现中 `_step` 使用了“虚拟腿池”加权，和开发文档写的“满4条后各 1/4”冲突。本工具采用满4条后各25%的模型；未满4条时按完整副属性池抽取，已有属性转为强化、未有属性才新增。

## 已知边界

- 这是单个御魂的强化价值判断，不计算整套搭配、式神面板、资源库存或凑套收益。
- 动态门槛依赖当前 `ios.json`，更换御魂池后推荐会随之变化。
- 输入没有历史强化次数时，程序只把当前数值当作确定的已有评分；这不影响从当前状态到 +15 的未来概率。
